1. EXECUTIVE SUMMARY & MISSION
--------------------------------------------------------------------------------
Closly is an advanced, high-performance fashion ecosystem designed to bridge the
gap between physical wardrobes, social fashion sharing, and automated affiliate
e-commerce.

Most fashion apps either focus purely on social inspiration (e.g., Pinterest,
Instagram) or standard retail e-commerce. Closly unites these domains through:
1. Digital Wardrobe Digitization: Allowing users to catalog their real-life clothes
   effortlessly using camera snapshots analyzed by OpenAI GPT-4o Computer Vision.
2. Cost-Per-Wear Financial Intelligence: Providing real-time metrics on wardrobe
   utilization, calculating exact cost-per-wear to incentivize sustainable fashion.
3. Real-Time Social Network: Full outfit blogging with multi-image carousels,
   24-hour ephemeral stories, following feeds, and real-time 1-on-1 WebSocket chat.
4. Intelligent Affiliate Commerce: Automated background ingestion of product feeds
   from Awin and Rakuten Advertising networks, matching products against user
   Style DNA to generate personalized "For You" shopping streams.
5. Gamified Loyalty Economy: A dual-balance points ledger (spendable vs. lifetime
   tier points) rewarding platform engagement, wardrobe uploads, and purchases.

2. SYSTEM ARCHITECTURE & HIGH-LEVEL DESIGN
--------------------------------------------------------------------------------
The Closly backend is architected to handle high-concurrency mobile and web
traffic with low latency and robust fault tolerance.

A. Networking & Gateway Layer:
   - External HTTPS/WSS requests hit an edge reverse proxy (Nginx or Cloudflare).
   - HTTP traffic and persistent WebSocket connections are unified under Daphne,
     an asynchronous ASGI server running on port 8000.
   - WhiteNoise provides optimized static file delivery with cache headers.

B. Application & Domain Layer:
   - Built on Django 5.2 and Django REST Framework (DRF) 3.16.
   - Business logic is partitioned into modular, single-responsibility apps:
     `users`, `closet`, `social`, `affiliate`, `rewards`, and `notifications`.
   - Real-time communications use Django Channels 4.0 backed by Redis channel layers.

C. Asynchronous Processing Layer:
   - Celery 5.3+ handles heavy workloads off the main request-response cycle.
   - Celery Worker manages AI vision queues, push notification broadcasts, and feed
     bulk updates.
   - Celery Beat maintains recurring cron tasks (hourly story cleanups, daily
     notification purges, and scheduled affiliate feed syncs).

D. Data & Persistence Layer:
   - Primary Database: PostgreSQL 16 Alpine running in Docker, tuned for fast
     indexed lookups on UUIDs, foreign keys, and status flags.
   - In-Memory Cache: Redis 7 Alpine serving as the Celery message broker, Django
     cache backend, WebSocket channel layer, and translation cache.
   - Media & Asset Storage: Dual-mode architecture supporting S3-compatible cloud
     buckets (AWS S3, Cloudflare R2, Hetzner Storage Box) with automatic fallback
     to local Docker volumes.

3. IN-DEPTH CORE MODULE BREAKDOWN

================================================================================
MODULE 1: USERS & AUTHENTICATION (`users`)
================================================================================
The user identity system is built with high security standards, privacy
compliance, and deep personalization.

Key Features & Engineering Details:
- UUIDv4 Primary Keys: Eliminates sequential ID enumeration risks, preventing
  malicious scraping or profile guessing.
- Authentication Vectors:
  * Standard Email + Password with custom UserManager.
  * Time-based One-Time Password (OTP) verification for signups and password
    resets with a 10-minute expiry window and automatic database purge.
  * Firebase Authentication integration supporting Google and Apple Sign-In
    tokens validated via the Firebase Admin SDK.
  * JWT (JSON Web Tokens) with rotation and automated blacklisting via SimpleJWT.
- Deep Style DNA Onboarding:
  Captures a multi-dimensional style profile during user onboarding:
  * Style Match Keys: Streetwear, Minimalist, Classic, Bohemian, Romantic, Preppy.
  * Occasions: Work-casual, smart, gym, weekend, travel, formal, lounge.
  * Body Measurements: Body type (Hourglass, Pear, Rectangle, etc.), height,
    weight, chest, waist, hip, and shoe size.
  * Skin Tone & Palette: Stored as hex color codes (e.g. #F5CBA7) paired with
    curated palettes (Neutral Minimalist, Bold & Rich, Soft Romantic, Earthy Warm).
  * Brand Affinities: Grouped taxonomy across Everyday, Popular, and Designer labels.
- Dynamic Response Translation Middleware:
  A custom middleware intercepts outgoing JSON responses. If the user's
  `preferred_language` is not English (e.g., Hindi, Portuguese), non-technical
  strings are translated on the fly via `deep-translator`. Technical keys, IDs,
  URLs, and hex codes are skipped via regex matching, and results are cached in
  Redis to ensure zero perceptible latency penalty.
- Account Deletion & Privacy Compliance:
  Implements self-service account deletion and profile data erasure workflows
  compliant with GDPR and App Store guidelines, using secure email verification tokens.
- Public Web Profiles:
  Server-side rendered profile cards (`/u/<user_id>/`) featuring OpenGraph meta tags
  for social media sharing and custom referral code generation (`CLO-XXXXXX`).


================================================================================
MODULE 2: SMART DIGITAL WARDROBE & AI SCANNER (`closet` + `dress-analyzer-ai`)
================================================================================
This module digitizes physical closets and transforms garments into actionable
fashion and financial data.

Key Features & Engineering Details:
- Wardrobe Organization:
  Categorizes items into Tops, Bottoms, Shoes, Dresses/Outerwear, and Accessories.
  Tracks purchase price, brand, color, size, wear count, and last worn date.
- AI Computer Vision Engine:
  Integrates directly with OpenAI GPT-4o Vision (as well as a dedicated internal
  FastAPI analyzer service in `dress-analyzer-ai`).
  * Scans garment images to detect category, gender suitability, primary and
    secondary colors, pattern types (solid, striped, check, floral, etc.), brand
    logo identification, and estimated retail market price.
- Concurrency Semaphore & Rate-Limit Shield:
  To prevent OpenAI 429 "Too Many Requests" errors during traffic spikes, the
  scanner implements an internal `BoundedSemaphore` concurrency gate alongside
  SHA-256 image hashing. Repeating a scan on the same image hits the Redis cache
  instantly without making outbound LLM calls.
- Cost-Per-Wear (CPW) Intelligence:
  A "Wear Today" action increments the garment's wear counter and recalculates:
  `per_wear_cost = price / times_worn`. This shows users the real value of their
  clothing choices over time.
- Closet Audit & Health Dashboard:
  Provides analytics on wardrobe color distribution, underutilized garments,
  and overall closet efficiency scores.

MODULE 3: SOCIAL NETWORK, 24H STORIES & REAL-TIME CHAT (`social`)
================================================================================
A complete social media experience tailored specifically for fashion enthusiasts.

Key Features & Engineering Details:
- Today's Outfit Publishing:
  * Supports single and multi-image carousels (up to 4 high-resolution photos)
    with preserved display order.
  * Allows tagging items directly from the user's digital closet.
  * Adds weather tags, style categories, and visibility toggles (Public vs. Private).
- Multiple Feed Streams:
  * Public Newsfeed: Global community outfits ordered chronologically.
  * Following Newsfeed: Filtered feed showing looks exclusively from followed creators.
  * Explore Feed: Algorithmically highlights trending creators and styles.
  * Your Day Feed & Outfit Calendar: Personal timeline and monthly calendar
    view mapping out historical outfits worn day-by-day.
- 24-Hour Ephemeral Stories:
  * Instagram/Snapchat-style disappearing stories with image upload and captions.
  * View tracking with viewer deduplication and love reactions.
  * Celery Beat hourly background task automatically deactivates expired stories.
- Real-Time WebSocket Direct Messaging (`ChatConsumer`):
  * Low-latency, bidirectional 1-to-1 chat powered by Daphne and Channels-Redis.
  * Secure token authentication via WebSocket query parameter (`?token=<jwt>`).
  * Live typing status, message read receipts, and online/offline presence tracking.
  * Rich attachment support: Text, images, shared digital closet outfits, and
    shared affiliate product cards directly inside the conversation thread.


================================================================================
MODULE 4: AUTOMATED AFFILIATE COMMERCE ENGINE (`affiliate`)
================================================================================
Monetization and product discovery engine connecting users with international
retail brands.

Key Features & Engineering Details:
- Multi-Network Data Ingestion:
  * Integrates with Awin and Rakuten Advertising networks.
  * Normalizes third-party product data into a unified schema: sale price,
    RRP (recommended retail price), calculated discount percentage, currency,
    brand, advertiser, high-res images, and affiliate deep links.
- High-Throughput Streaming Ingestion (`sync_awin_feeds`, `sync_rakuten_feeds`):
  * Streams large gzip CSV feeds directly over HTTP into memory without filling disk.
  * Executes bulk upserts (`bulk_create` with conflict updates) in optimized
    chunks of 1,000 records.
  * Deactivates obsolete products in an atomic O(1) database operation.
- Personalized "For You" Shopping Feed:
  * Matches products against the user's Onboarding Style DNA (preferred brands,
    color palettes, preferred clothing categories) to generate an individualized
    shopping feed.
- Conversion Analytics:
  * Tracks user intent via `ProductClick` when a user taps "Buy", recording the
    interaction before redirecting through the merchant's tracked affiliate link.
- Product Wishlist:
  * Enables users to "Love" or "Save" affiliate items into a private wishlist.


================================================================================
MODULE 5: GAMIFICATION & DUAL-BALANCE LOYALTY SYSTEM (`rewards`)
================================================================================
An incentive engine designed to maximize platform retention and user activity.

Key Features & Engineering Details:
- Dual-Balance Architecture:
  * `available_points`: Spendable points that expire after 60 days if unused.
  * `lifetime_points`: All-time earned points that permanently lock the user's
    VIP tier status and NEVER decrease when spendable points expire.
- Tier Progression:
  * Bronze: 0 – 2,000 points
  * Silver: 2,000 – 5,000 points
  * Gold: 5,000 – 10,000 points
  * Platinum: 10,000 – 50,000 points
  * Diamond: 50,000+ points
- Point Accrual Rules:
  * Sharing an Outfit Look: +120 points
  * Inviting Friends via Referral Code: +200 points
  * Making a Partner Purchase: +200 points
  * Adding an Item to Digital Closet: +50 points
- Immutable Ledger:
  * Every point movement is recorded in `RewardPointTransaction` with action types,
    reference IDs, expiration timestamps, and auditing metadata.


================================================================================
MODULE 6: HYBRID NOTIFICATIONS ENGINE (`notifications`)
================================================================================
- Dual-Channel Dispatch:
  * Mobile Push: Dispatched to iOS and Android devices via Firebase Cloud Messaging (FCM).
  * In-App Notifications: Persistent inbox notifications tracking read/unread status.
- Triggered Events:
  * Outfit likes, new followers, direct messages, point awards, tier upgrades,

4. INFRASTRUCTURE, DOCKER & CLOUD SERVICES
--------------------------------------------------------------------------------
Closly is containerized with Docker and Docker Compose for zero-friction local
development and standardized production deployments.

Services in `docker-compose.yml`:
1. `closly_postgres`: PostgreSQL 16 Alpine database with health checks.
2. `closly_redis`: Redis 7 Alpine message broker and caching layer.
3. `closly_web`: Daphne ASGI server hosting the Django application and WebSockets.
4. `closly_celery_worker`: Background worker handling async tasks.
5. `closly_celery_beat`: Periodic scheduler triggering recurring cron tasks.

Storage Abstraction:
- Configured with `django-storages` and `boto3`.
- By setting `USE_S3=True`, media uploads route seamlessly to AWS S3, Cloudflare R2,
  or Hetzner Storage Box.
- When `USE_S3=False`, media defaults to local Docker volumes, ensuring complete
  offline development capability without external cloud dependencies.

5. KEY TECHNICAL CHALLENGES & ENGINEERING SOLUTIONS
--------------------------------------------------------------------------------

CHALLENGE 1: High-Volume Affiliate Feed Ingestion Without Server Exhaustion
- Problem: Daily product feeds contain hundreds of thousands of rows in compressed
  gzip format. Downloading entire files and processing row-by-row exhausted server
  RAM and locked database tables.
- Solution: Built a streaming decompressor using Python's `gzip` and `requests`.
  Data is processed line-by-line, transformed, and inserted in batches of 1,000 using
  Django's `bulk_create(update_conflicts=True)`. Stale products are deactivated with
  a single indexed SQL update query.

CHALLENGE 2: Preventing LLM Rate Limits in AI Wardrobe Scanning
- Problem: Simultaneous camera uploads from multiple users caused sudden spikes
  in OpenAI API calls, leading to HTTP 429 rate limit errors.
- Solution: Implemented a two-stage defense:
  1. A thread-safe `BoundedSemaphore` restricting concurrent API calls to 15.
  2. A SHA-256 image hashing cache in Redis that detects identical images and
     returns cached analysis in 5ms without outbound API calls.

CHALLENGE 3: Real-Time WebSockets Under Asynchronous Architecture
- Problem: Standard WSGI web servers (like Gunicorn) cannot handle long-lived
  persistent WebSocket connections for chat.
- Solution: Adopted Daphne as the ASGI application server alongside Django Channels
  and `channels-redis`. Authentication occurs during connection handshake via JWT
  token query parsing, mapping users to unique Redis channel groups.

CHALLENGE 4: Fair Gamification with Expirable Points
- Problem: In loyalty systems, points should expire to reduce financial liability,
  but degrading a user's hard-earned VIP status causes severe user churn.
- Solution: Engineered a dual-balance ledger separating `available_points` (spendable,
  60-day expiry) from `lifetime_points` (permanent achievement points that anchor
  the user's VIP tier forever).
